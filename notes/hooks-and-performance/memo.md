# memo

> دسته: React Hooks & Performance

از این دستور زمانی استفاده میشود که بخواهیم از `rerender` های اضافه کامپوننت جلوگیری کنیم:

```jsx
const Users = memo(function Users({ name }) { 👈

  return <div>{ name }</div>;

});
export default Users;
```

```jsx
function Users({ name }) {

  return <div>{ name }</div>;

};

export default memo(Users); 👈
```

با استفاده از یکی از روش های بالا تمام تابع کامپوننت را درون `memo` قرار میدهیم

در این حالت وقتی که از این کامپوننت درون یک کامپوننت دیگر استفاده کنیم و کامپوننت والد به هر دلیلی `rerender` شود کاموپننت `memo` شده, `rerender` نخواهد شد مگر اینکه `prop` هایی که به آن پاس داده شده‌اند عوض بشوند(در این صورت (عوض شدن `prop` های کامپوننت `memo` شده)با `rerender` شدن کامپوننت والد کامپوننت فرزند هم `render` میشود)

نکته: اگر یک تابع `handler` به عنوان `prop` به کامپوننت فرزند `memo` شده پاس داده شده باشد `memo` به درستی کار نخواهدکرد چون در هر بار `rerender` شدن کامپوننت والد این تابع `handler` هم از ابتدا ساخته خواهد شد و در نتیجه `reference` متفاوتی هم خواهد داشت در نتیجه در `prop` کامپوننت فرزند چون `reference` متفاوت است انگار که `prop` تغییر کرده است و در نتیجه `memo` به درستی نمیتواند کار کند (در کاموپننت هایی که حداقل یک `prop` از نوع تابع `handler` داشته باشند کار‌آمد نخواهد بود)

برای رفع این مشکل، روش‌های متعددی وجود دارد؛ از جمله استفاده از `useCallback` برای پایدار نگه‌داشتن توابع، و `useMemo` برای پایدار نگه‌داشتن آرایه‌ها و اشیاء. در غیر این صورت می‌توان با دادن `compare function` به `memo`، مقایسه‌ی عمیق‌تر یا سفارشی انجام داد.

این متد یک آرگومان دوم به‌صورت تابع دریافت می‌کند که مقادیر قبلی و جدید `props` را برمی‌گرداند. با اعمال شروط لازم در این تابع، می‌توان تعیین کرد که آیا کامپوننت نیاز به رندر مجدد دارد یا خیر. برای مثال، زمانی که یک `prop` از نوع آرایه است — چون `memo` به‌تنهایی قادر به تشخیص تفاوت بین دو آرایه نیست می‌توانیم این بررسی را خودمان انجام دهیم.

```jsx
function Users({ name }) {
  return <div>{name}</div>;
}

export default memo(Users, (oldProps, newProps) => {
  return (
    oldProps.items.length === newProps.items.length &&
    oldProps.items.every((item, i) => item === newProps.items[i])
  );
});
```

این تابع `compare` مشخص می‌کند که آیا `props` برابر هستند یا نه. اگر `true` برگردونه (یعنی `props` برابرن)، `memo` از `rerender` جلوگیری می‌کند؛ و اگر `false` برگردونه (یعنی `props` فرق کردن)، کامپوننت `rerender` می‌شود.

### نکات تکمیلی درباره memo:

<ul>
  <li>
 فقط یه shallow comparison انجام می‌ده: یعنی فقط سطح اول prop رو چک می‌کنه. برای آرایه/شیء، reference رو مقایسه می‌کنه نه محتوا رو.
  </li>
  <li>
 برای کامپوننت‌های کوچیک همیشه سود نداره: چون خودش یه هزینه‌ی مقایسه داره. استفاده‌ی بی‌جا از memo می‌تونه performance رو بدتر کنه.
  
  </li>
  <li>
  اگه کامپوننت children می‌گیره، چون هر بار reference جدید داره، memo بی‌اثر می‌شه.
  </li>
  <li>
  به memo و useMemo دقت کن این دوتا فرق دارن. memo برای کامپوننت‌هاست، useMemo برای مقادیر.
  </li>
</ul>
